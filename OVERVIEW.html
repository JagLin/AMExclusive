AMExclusive. 架構概覽

Apple Music for Windows 的注入式 mod：WASAPI 獨占輸出、強制最高音質（ALAC Hi-Res），目標是 bit-perfect 播放。本頁整理程序拓樸、hook 點、音訊資料路徑與建置流程。

程序拓樸

Apple Music 啟動時，Windows 工作排程器（觸發條件：Microsoft-Windows-AppModel-Runtime/Admin EventID 201，ImageName = AppleMusic.exe）會拉起 Broker。Broker 綁定該 AppleMusic.exe PID，對兩個 Apple 程序做 CreateRemoteThread + LoadLibraryW 注入，並作為 named pipe 的中樞。

am-exclusive-broker.exe
companion · 生命週期綁定 AppleMusic.exe PID · IPC 中樞 · 持久化 ini · 錯誤對話框
↓ 注入 DLL　·　↕ named pipe Message（固定大小、pack(1)）
AppleMusic.exe
WinUI 3 前端
+ am-exclusive-ui.dll
Role::Ui · 設定頁開關 · transport 手勢
AMPLibraryAgent.exe
實際解碼與播放程序
+ am-exclusive-hook.dll
Role::Agent · 音質鎖 · audio core v2

Broker 在綁定的 host 結束時退出；Agent 殘留不會讓它繼續存活。工作排程器設定為 MultipleInstances = StopExisting，所以每次新啟動的 Apple Music 都會換一個新的 companion。

IPC 協定

IpcProtocol.h：magic "AMIP"，protocol 2.0。每則訊息都是同一個 trivially-copyable 的 Message 結構（< 4096 bytes），依 type 解讀欄位。pipe 名稱與安全描述元綁定目前使用者的 SID；Broker 會比對 GetNamedPipeClientProcessId 與 senderPid。

MessageType方向語意
Hello / HelloAckclient ↔ Broker握手；新 Agent PID 會把 state 重設為 WaitingForStream
SetEnabledUi → Broker使用者切換獨占；寫入 ini mode=exclusive|probe
SetHardwareBufferUi → Broker1–100 ms，寫入 period_100ns，下一首生效
StatusChangedBroker → all / Agent → BrokerBroker 擁有 enabledIntent，Agent 的事件只能更新 runtime state
AttemptFailedAgent → Broker結束本次嘗試，但保留使用者 intent，下一首重新 arm
TransportIntentUi → Broker → Agentdetail 帶動作（play_pause、skip_arm、skip、seek_begin、seek_commit、selection_arm），generation 帶手勢 epoch

RuntimeState：Off → Requested → WaitingForStream → Probing → Initializing → AlignRetry → Active → DisablePending / FailedOff。

路徑一：音質鎖

只要 hook 安裝成功就啟用，不受 UI 獨占開關影響（QualityLockHookLoop）。只有當 Apple 的偏好設定為 losslessEnabled 且 preferredStreamPlaybackAudioQuality 為 15 或 20 時才介入。

AVCFPlayerItemSetVariantPreferences

強制 lossless bit 0x8，清掉 spatial/immersive bit 0x3，避免被切換到 AAC 相容分支。

AVCFPlayerItemSetPreferredMaximumAudioSampleRate

tier 20 時把上限拉到 192 kHz。

FigAlternateEligibleLosslessAudioFilterCreate

改用只允許 alac / qlac 的嚴格 subtype filter（LosslessQualityLock.cpp）。strict 模式下不會 fallback 到 Apple 的自適應 filter，寧可等待也不降級。

私有 ABI（filter class table slot、CoreMedia RVA 指紋、ALAC cookie offset、local seek 呼叫堆疊 RVA）集中在 ApplePrivateOffsets.h。Apple Music 改版時，要從這裡重新驗證。

路徑二：獨占輸出（audio core v2）

這條路徑受 UI 開關控制。Apple 的解碼與排程維持原樣（kNativeAcquisitionPassthrough = true）；mod 只鏡像解碼後的 float32 P0，並接手實體端點。

1
Converter 登記 — AudioConverterNew[Specific] / SetProperty
AudioCoreConverterRegistry：固定槽位、全 atomic，記錄來源格式、ALAC cookie 位元深度，以及 decoder ↔ P0 converter 的對應。
2
Graph 驗證 — AudioUnitSetProperty / Initialize / AudioOutputUnitStart
先確認 active AudioUnit graph，才把 converter 綁定到目前的 generation。綁定靠 observation id，不靠建立順序推斷。
3
P0 擷取 — AudioConverterFillComplexBuffer → ApplePcmTap
callback 執行緒只把 float32 複製進預先配置的 SPSC queue（PcmQueue），不配置記憶體也不等待。
4
整數化 — ExactSampleMapper / LocalFloatIntegerizer
整數來源（ALAC 16/24-bit）必須精確落在原本的 PCM lattice 上（×2³¹ 後不得有小數），否則 fail-closed，不做 rounding 或 dither。本機 float32 檔案另走 round-half-even 量化成 PCM32，這一類不算 bit-perfect。
5
Sink — QueuedPcmSource → WasapiExclusiveSink
實作 IIntegerPcmSource::Fill(int32*, …)。sink 以 event-driven 的 WASAPI 獨占模式開在預設端點（eRender / eConsole），會嘗試多組格式候選與 buffer 對齊重試。source 暫時不足時回傳 kAudioSourceWouldBlock，sink 會暫停而不是補靜音。
6
壓掉原生輸出 — CoCreateInstance → MMDevice vtable → NativeRenderGateProxy
包住 Apple 的 IAudioClient / IAudioRenderClient。gate 進入 Active 後，原生輸出改為 shadow（讓 Apple 的排程繼續運轉，但不出聲）；handoff 時釋放 Apple 的 shared client，讓出端點。

AudioCoreGate 狀態機

Off→ Armed→ Capturing→ Prebuffered→ Active · Faulted

每次 UI 切換都會遞增 generation，舊 token 自動失效。只有 CommitCutover（sink 已 Start 且已 prebuffer）會讓 ShouldSuppressNative() 變成 true。

建置與安裝

只能在 Windows 上建置：需要 MSVC、Windows 11 SDK（cppwinrt.exe）、CMake ≥ 3.24 與 PowerShell。WinUI projection 由 Microsoft.UI.Xaml.winmd 產生，來源可以是本機安裝的 Apple Music 套件，或 Get-WinUIMetadata.ps1 從 NuGet 下載（會驗 SHA-256）。

cd mod
.\scripts\Get-WinUIMetadata.ps1 -OutputDirectory .\build\winui-metadata
.\scripts\Build-Mod.ps1 -Configuration Release -WinUIMetadataDirectory .\build\winui-metadata
# → mod\build\dist\AMExclusive-Setup.exe
  • CI：.github/workflows/build-setup.yml，只能手動觸發（workflow_dispatch），在 windows-2022 上建置並執行 --extract-test，產出的 artifact 保留 14 天。
  • MinHook 透過 FetchContent 抓取（v1.3.4）；SPSCQueue 以原始碼放在 third_party/。
  • 安裝腳本 Install-Mod.ps1 會先停掉 Apple Music / Agent / Broker，保留舊 ini 的 mode 與 period_100ns，用 icacls 設定目錄權限（使用者、SYSTEM、ALL APPLICATION PACKAGES 唯讀），寫入 manifest，再執行 Register-Companion.ps1。
  • 目前沒有自動化測試；/mod/tests/ 在 .gitignore 裡。

注意事項

版本綁定。私有 RVA 與呼叫堆疊指紋只在 Apple Music 1.6.4.90 驗證過。其他版本的音質鎖會因指紋不符而停用（fail-closed），但 UI 樹結構的變動不一定能被偵測到。
  • 端點固定是預設裝置；IPC 的 endpointId 欄位與 WasapiSinkConfig::endpointId 已經存在，但 UI 沒有開放裝置選擇。
  • IIntegerPcmSource 是 sink 與資料來源之間的抽象邊界；AudioCoreCoordinator 目前直接持有具體型別 WasapiExclusiveSink。
  • HookDll.cpp 約 3.6k 行，混合了正式路徑與 native trace 診斷；SampleConversion.h 是空檔。
  • 本 repo 是 JagLin/AMExclusive，fork 自 AntiOblivionis/AMExclusive，README 的連結仍指向上游。
